# 权限说明（审核表单直接粘贴）

商店后台会逐项问「为什么需要这个权限」，把下面的文字贴进去即可。

---

## 权限 Permissions

### `storage`

```
保存便签内容、颜色、置顶状态和界面设置。所有数据写入本机的 chrome.storage.local，不经网络传输，也不与任何第三方共享。这是扩展的核心功能（持久化笔记），无法用其他方式实现。
```

### `unlimitedStorage`

```
便签是纯文本，但在长期使用中可能积累大量条目（每条独立存储，另含导入的备份数据）。申请此权限是为了避免触发默认存储配额后无法写入，导致用户丢失新记录。扩展不存储任何媒体文件或网页内容。
```

### `sidePanel`

```
提供「侧边栏」这一核心使用形态。用户点击工具栏图标或按 Ctrl+Shift+Y 时，在浏览器侧边栏打开便签界面，这样浏览网页时笔记始终可见且不遮挡页面内容。
```

### `contextMenus`

```
在网页右键菜单中提供两项操作：「把选中文字存为便签」和「打开全屏日记本」。用于让用户在不离开当前页面的情况下快速记录。
```

### `clipboardWrite`

```
便签界面里的「复制」按钮，把当前便签的纯文本写入系统剪贴板，方便用户粘贴到其他应用。只在用户点击按钮时调用，不读取剪贴板内容。
```

## 主机权限 Host permissions

### 内容脚本 `<all_urls>`

```
这是「网页浮窗」功能的前提：用户选择把便签浮在当前网页上时，需要在该页面注入一个轻量的 UI 容器（Shadow DOM + iframe），用来显示可拖动、可缩放的便签面板。

脚本的行为严格受限：
· 不读取、不修改、不上传页面内容（不访问 DOM 文本、不注入广告、不埋点）
· 只在页面里创建一个带 shadow root 的空容器，用来承载扩展自己的 iframe
· 只在用户主动开启浮窗或点击「插入」时，才向用户指定的输入框写入便签文字

之所以需要全部网站，是因为用户可能在任何页面上想要记东西（文档、邮件、后台系统、内部工具），无法预先限定域名。
```

### `web_accessible_resources` 的 `matches: <all_urls>`

```
允许扩展内部的界面文件 panel.html 被注入到当前网页的 iframe 中显示——这就是浮窗面板本身。该文件只能由扩展自己的内容脚本创建，不向页面脚本暴露任何数据，也不含任何远程资源。
```

## 数据使用（Data usage）

```
本扩展不收集任何用户数据。

· 便签内容、颜色、置顶、界面位置等，全部保存在用户本机的 chrome.storage.local，不离开设备
· 没有网络请求（代码中不存在 fetch / XMLHttpRequest / WebSocket）
· 没有远程代码、没有动态加载的脚本，所有资源都打包在扩展内
· 没有分析统计、没有广告、没有崩溃上报
· 不读取浏览历史、不读取剪贴板内容、不读取网页正文
· 用户可用「导出」得到自己的 JSON 备份，「导入」恢复；卸载扩展即清除全部数据

单一用途：一个便签扩展，让用户在当前浏览器里快速记录、查看和复制纯文本便签。
```

---

## 审核若有疑问，可用这段解释

```
关于 <all_urls>：这是「网页浮窗」形态的技术前提，而不是为了读取用户浏览内容。扩展的内容脚本只做三件事：
1）在页面里创建一个 shadow DOM 容器（默认隐藏）；
2）用户开启浮窗时，在其中放一个指向扩展自身 panel.html 的 iframe；
3）用户点击「插入」时，把便签文字写入当前聚焦的 input / textarea / contenteditable。
代码可自行核验：content.js 中不存在任何读取页面文本、收集链接或上报的调用。
```
