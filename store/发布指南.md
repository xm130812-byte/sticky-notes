# 发布指南 · 从「开发者模式」变成正式扩展

## 先说结论

Chrome 和 Edge 只信任两种来源的扩展：**官方商店**，或者**由管理员通过企业策略下发**。除此之外没有第三条路——把 `.zip` 或 `.crx` 拖进浏览器这条路在 Windows 上早就被封了（会报 `CRX_REQUIRED_PROOF_MISSING` 或「此扩展程序不是来自 Chrome 网上应用店」）。所以「不用开发者模式」= 必须走商店。

三条可行路线：

| 路线 | 费用 | 谁能装 | 适合 |
| --- | --- | --- | --- |
| Chrome 网上应用店（**不公开**） | 一次性 $5 | 拿到链接的人 | 自己 + 朋友，最省事 |
| Edge 附加组件商店 | 免费 | 拿到链接的人 | 只用 Edge / 不想花钱 |
| 企业策略强制安装 | 免费 | 受管设备 | 公司内几台到几千台机器 |

> **推荐**：先发 Chrome 商店的**不公开（Unlisted）**版本。它不进搜索、不进推荐，只有拿着链接的人能装，但安装过程和装任何正式扩展一样，不需要开发者模式。

---

## 一、发到 Chrome 网上应用店

### 1. 注册开发者账号（一次性 $5）

1. 打开 <https://chrome.google.com/webstore/devconsole>
2. 用 Google 账号登录，支付一次性注册费（$5，信用卡）
3. 同意开发者协议

### 2. 上传扩展包

1. 点右上「新增项目」
2. 上传 `sticky-notes-1.2.0-store.zip`
   （这个包里**不含** `docs/`、`store/` 和 `key` 字段，是商店要求的干净结构）
3. 上传后商店会自动填好名称、版本、描述

### 3. 填写商品详情

对照 `商店文案.md` 直接复制粘贴：

- **名称**：便签 · Sticky Notes
- **简述**（≤132 字符）：见文案文件
- **详细说明**：见文案文件
- **类别**：生产工具（Productivity）
- **语言**：中文（简体）
- **图标**：已在包里（128×128）
- **截图**：上传 `store/screenshots/` 下的 5 张（1280×800，全部是真实界面截图）
- **宣传图片**（可选）：不用传也能过审

### 4. 隐私与权限（这一步决定审核快慢）

按 `权限说明.md` 填写：

- **单一用途说明**：一句话讲清楚「这是一个便签扩展」
- **权限理由**：逐条粘贴，`<all_urls>` 那条一定要写清楚「只是为了在网页上显示浮窗，不读取页面内容」
- **数据使用**：勾选「不收集任何用户数据」，并说明数据只存在本机
- **隐私政策网址**：如果勾了「不收集数据」，这一项可以不填；想稳妥一点就把 `privacy-policy.html` 放到 GitHub Pages 上再填进去

### 5. 可见性：选「不公开」

| 选项 | 含义 |
| --- | --- |
| 公开 Public | 商店里能搜到 |
| **不公开 Unlisted** | 搜不到，**只有拿到链接的人能装**（推荐） |
| 私密 Private | 只有你指定的测试者 / Google Workspace 组织能装 |

选「不公开」后，过审会给你一个形如
`https://chromewebstore.google.com/detail/xxxxxxxx`
的链接，发给谁谁就能点「添加至 Chrome」，全程不需要开发者模式。

### 6. 提交审核

- 点「提交以供审核」
- 一般 **几小时到 3 天**；新开发者 + `<all_urls>` 偶尔会拖到 1～2 周
- 被退回时会在开发者控制台给出具体条款，按提示改完重新提交即可，不会重复收费

## 二、发到 Edge 附加组件商店（免费）

如果电脑上主要用 Edge，这条更划算：**注册免费**，审核通常也比 Chrome 快。

1. 打开 <https://partner.microsoft.com/dashboard/microsoftedge/>
2. 用 Microsoft 账号注册开发者（个人开发者免费）
3. 新建扩展 → 上传同一个 `sticky-notes-1.2.0-store.zip`
4. 商品信息、截图、隐私声明与上面完全相同（`商店文案.md` 通用）
5. 可见性同样可以选「隐藏 / Unlisted」
6. 提交后审核约 1～7 天

Edge 商店装上的扩展在 Edge 里正常工作，也不需要开发者模式。

## 三、公司电脑 / 固定几台机器：企业策略

不需要商店，也不需要开发者模式，但需要**每台机器的管理员权限**。

1. 自托管：把扩展解压到一个固定目录（如 `C:\Program Files\StickyNotes`），再把 `manifest.json` 里的 `key` 换成你生成的公钥（可用 `openssl` 或 Chrome 打包时生成），得到固定 ID
2. 写注册表：

```
HKLM\SOFTWARE\Policies\Google\Chrome\ExtensionInstallForcelist
  1 = "<扩展ID>;https://your-server/updates.xml"
```

3. Edge 用 `HKLM\SOFTWARE\Policies\Microsoft\Edge\ExtensionInstallForcelist`
4. 重启浏览器，扩展自动安装并锁定（用户无法卸载），且**不需要开发者模式**

适合内部工具分发；个人自用没必要走这条路。

## 四、几个必须知道的影响

- **扩展 ID 会变**：商店版的 ID 由商店分配，和你本地解压加载的 ID 不同。`chrome.storage.local` 按 ID 隔离，所以**商店版是空的**。从开发者模式迁过去时，先在旧版「导出全部便签」，再在新版「导入」。
- **更新方式变了**：以后改代码只需把 `manifest.json` 的 `version` 加一，重新打包上传、提交审核，用户会在几小时内自动更新，不用再手动刷新扩展。
- **代码会被审核**：商店会做自动扫描 + 人工抽查。本扩展没有远程代码、没有网络请求，扫描不会有问题；人工审核主要看权限理由写得清不清楚。
- **不要指望「分享 crx」**：任何人拿到 crx 双击安装都会被浏览器拦下，这条路不存在。

## 五、如果你觉得审核太慢

`<all_urls>` 内容脚本是所有「网页浮窗」类扩展的通用做法，绝大多数能正常过审，但确实是最容易被追问的一项。如果想降低审核风险，可以把浮窗改成**按需注入**：

- 去掉 `content_scripts` 的 `<all_urls>`，改用 `activeTab` + `scripting`
- 用户第一次点「浮窗」时才注入脚本（之后在同一页面持续有效）

代价是：刷新页面后浮窗不会自动回来，需要再点一次。需要的话告诉我，我改一版专门用于商店提交。
